## Pages 一键部署

安装 Node.js 22 或更新版本。在 Pages 安装包目录打开 PowerShell：

```powershell
npm install
$env:CLOUDFLARE_API_TOKEN = '填写自己的Cloudflare API令牌'
$env:CLOUDFLARE_ACCOUNT_ID = '填写自己的账户ID'
$env:PAGES_PROJECT_NAME = 'xiazheteng-data'
npm run deploy:oneclick
```

脚本创建或复用 Pages 项目和 KV，绑定生产与预览环境，上传并发布。若账号只有一个，账户 ID 可以省略。令牌需要对应账户的 Pages 编辑、Workers KV 存储编辑权限；自动查询账户还需要账户读取权限。不需要区域 DNS 权限，脚本不修改域名解析。

首次新项目自动生成历史访问密钥，保存在安装包目录的 `.deploy-secrets.json`，不会上传。该文件用于本人查看和后续部署，应自行备份，不能提交到仓库或发给他人。已存在项目的密钥默认保留；明确设置 HISTORY_TOKEN 时才更新。

## 环境变量批量导入

复制 `数据站环境变量批量导入模板.json` 为个人变量文件。**引号内目前是用途与示例，必须替换为真实值；不需要的项删除。不能直接把说明文字导入生产。**

```powershell
$env:ENV_IMPORT_FILE = '.\个人变量.json'
npm run deploy:oneclick
```

支持导入的运行变量只有以下两项：

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| HISTORY_TOKEN | 加密密钥 | 至少 24 位随机字符串，所有历史读写必须携带该密钥。网页“历史数据”的云端连接填写相同密钥。 |
| ALLOWED_ORIGINS | 普通文本，可选 | 逗号分隔的完整来源地址，包含协议和端口，不含路径。同域自动允许，无跨域需求时不设置。 |

部署工具变量 CLOUDFLARE_API_TOKEN、CLOUDFLARE_ACCOUNT_ID、PAGES_PROJECT_NAME、ENV_IMPORT_FILE 只在本机部署使用，不应当作为前端变量打包。

## 手动配置 Pages

1. 创建 Direct Upload Pages 项目，生产分支 main。上传完整 Pages 目录（含 `_worker.js`），推荐 Wrangler 上传以正确编译 Worker。
2. 创建 KV 命名空间，推荐名字 `xiazheteng-data-history`，绑定变量名必须是 `HISTORY_KV`。
3. 生产和预览环境都绑定同一个命名空间，并配置 HISTORY_TOKEN 加密变量。ALLOWED_ORIGINS 按需设置。
4. 兼容日期使用 2026-11-04。无框架、无构建命令；一键脚本自动生成上传目录 `.pages-dist`。
5. 修改绑定或变量后重新发布。打开站点“历史数据”，选择云端连接，接口地址填 https://xiazheteng-data.pages.dev/api/history，密钥填 HISTORY_TOKEN。

本项目**不需要 R2、D1、Durable Objects、S2 或额外 API Worker**。音乐属于静态资源；KV 只保存用户主动上传的历史数据。
